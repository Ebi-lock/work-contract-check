# レポート形式

## 出力先

1. **会話**: 「0. 前提」「1. サマリー」を表示し、続けて🔴高リスクを示す。ただし**🔴が5件を超える場合は、上位5件だけを全文で出し、残りはサマリー表の行に委ねて「詳細は保存したファイルを参照」と案内する**。ターミナルに数百行を流すと、結局どれが一番まずいのか伝わらない。依頼者が最初に知りたいのは「このまま締結して大丈夫か」「何から交渉すべきか」なので、そこに即答する。
2. **Markdown**: 全文を `契約書チェック結果_<契約書名>_<YYYYMMDD>.md` として契約書と同じディレクトリに保存。書き込めない場合はスクラッチパッドに保存し、パスを伝える。これは差分管理と再編集のための原本。
3. **HTML**: `python3 scripts/render_report.py <上のMarkdown>` で変換する。閲覧・共有・印刷はこちらが本体。依頼者にはHTMLのパスを先に伝える。

### レンダラが何をしてくれるか（HTMLを手書きしない理由）

- 🔴🟡🔵⬜ の色分けカード。`### [R-01] 第12条（損害賠償）` のような見出しを自動でカード化し、リスクは見出しの絵文字、なければ直前の `##` セクションの絵文字から決まる
- リスク階級での絞り込みボタン（🔴だけ表示して交渉の場で使う、といった読み方ができる）
- 左サイドの目次（`[R-01]` のような番号があればそれをアンカーにする）とスクロール追従
- `- **修正案**: 「…」` の行を、そのまま相手に送れるコピーボタン付きブロックにする。`推奨する条文案` `推奨条文案` `代替案` も同じ扱い
- 印刷スタイル（指摘カードがページまたぎで割れない、ナビとボタンは非表示）
- ダークモード、スマホ幅対応、外部依存なしの単一ファイル

つまり**テンプレートの記法どおりにMarkdownを書けば、HTMLの体裁は自動で付く**。逆に記法を崩すとカード化や絞り込みが効かなくなるので、見出しとリスク絵文字の書き方はテンプレートに従うこと。

タイトルを変えたい場合は `--title "..."`、出力先を変えたい場合は `-o path.html`。

## 指摘の粒度をリスク階級で変える

すべての指摘を同じ密度で書くと、件数が多い契約では🔴が🔵に埋もれる。階級ごとに書く量を変える。

| 階級 | 書く項目 | 目安 |
|---|---|---|
| 🔴 高 | 原文引用／問題／起こり得る事態／法的根拠／修正案／交渉の見込み（フル） | 1件あたり10〜20行 |
| 🟡 中 | 原文引用（該当部分のみ）／問題／修正案 | 1件あたり4〜8行 |
| 🔵 低・要確認 | 条項名＋一行の指摘＋確認すべきこと | 1件あたり1〜2行。表にまとめてよい |

指摘が20件を超えるようなら、🔵は個別の見出しを立てず表に集約する。

## 欠落した条項をどこに書くか

欠落にもリスク階級を付けるが、**本文の配置は「5. 記載のない条項とそのリスク」に一本化する**。🔴の欠落を高リスクのセクションに移すと、指摘が二箇所に散って追いにくい。代わりに:

- 「1. サマリー」の一覧表には、記載されている条項の指摘（R-xx）と欠落（M-xx）を**リスク順に混ぜて**並べる。ここが依頼者の入口になる。
- 会話に🔴を表示するときは、🔴の欠落も同じ優先度で並べて出す（読み手にとっては「書いてあって危険」も「書いていなくて危険」も同じ重さ）。
- 「5.」の本文では、🔴の欠落はフル構成、🟡🔵は上の表の粒度で書く。

## 番号の付け方

- `R-xx` … 記載されている条項の問題（Risk）
- `M-xx` … 欠落（Missing）
- `L-xx` … 法令抵触（Legal）

サマリー表と本文で同じ番号を使い、依頼者が行き来できるようにする。

## 書くときの注意

- **引用は原文のまま**。要約した引用は、後で相手と交渉するときに使えない。長い条項は該当部分だけを引用し、省略箇所は「（中略）」と示す。
- **条番号を取り違えない**。棚卸しの段階で作った条項一覧を参照する。
- **「〜と思われます」を重ねない**。判定できることは判定し、判定できないことは「〜の事実を確認する必要があります」と行動に落とす。
- **妥当な条項の逐条解説はしない**。件数だけ示す。レポートが長くなるほど、本当に重要な🔴が埋もれる。
- **修正案は、そのまま相手に送れる文章にする**。「上限を設けるべき」ではなく、条文の形で書く。
