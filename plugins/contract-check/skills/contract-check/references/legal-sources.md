# 法令の調べ方

契約書レビューで最も信用を失うのは、**存在しない条文番号を添えて断定すること**。法令名も条番号も改正で変わる（例：下請代金支払遅延等防止法は2025年改正で「製造委託等に係る中小受託事業者に対する代金の支払の遅延等の防止に関する法律」に改称、略称は取適法／中小受託取引適正化法、2026年1月1日施行。旧3条の書面交付義務は新4条、旧4条の禁止行為は新5条に移動している）。条文に言及するときは必ず取得してから書く。

## 1. e-Gov法令検索 — 現行条文の一次情報

<https://laws.e-gov.go.jp>

同梱スクリプトがこのサイトの法令API Version 2 を叩く。APIキー不要。

```bash
# 契約チェックで頻出する法令のIDを一覧（略称から引ける）
python3 scripts/egov.py laws

# 法令名の部分一致で law_id を探す
python3 scripts/egov.py search 労働者派遣
python3 scripts/egov.py search 特定受託

# 条文を取得（第1引数は略称・正式名称・law_id のいずれでも可）
python3 scripts/egov.py article 民法 641
python3 scripts/egov.py article 民法 398-2        # 第398条の2（枝番はハイフン）
python3 scripts/egov.py article 322AC0000000049 15
python3 scripts/egov.py article 労働契約法 18 --json   # 生JSONが必要なとき

# 条文本文の全文検索（どの法律に書いてあるか分からないとき）
python3 scripts/egov.py keyword 秘密保持 --limit 5
```

出力には**最終改正施行日**が含まれる。これが将来日付なら、まだ施行されていない条文を見ている可能性があるので、レポートでは施行日を併記する。

レポートで出典を示すときは `https://laws.e-gov.go.jp/law/<law_id>` の形式でリンクする（条文単位のアンカーは安定しないので、法令ページのURLと条番号をテキストで書く）。

### スクリプトを使わず直接叩く場合

```bash
curl -s "https://laws.e-gov.go.jp/api/2/laws?law_title=民法&limit=3"
curl -s "https://laws.e-gov.go.jp/api/2/law_data/129AC0000000089?elm=MainProvision-Article_415&json_format=light"
curl -s "https://laws.e-gov.go.jp/api/2/keyword?keyword=営業秘密&limit=3"
```

`elm` は法令XMLの要素指定。`MainProvision-Article_415`（本則第415条）、`MainProvision-Article_398_2`（第398条の2）、`SupplProvision[1]`（附則）。API仕様は <https://laws.e-gov.go.jp/api/2/swagger-ui/>。

### 旧下請法 → 取適法の条番号対応

2025年改正で条番号が繰り上がった。古い解説記事や旧版の雛形は旧番号を使っているので、そのまま引用すると誤りになる。

| 内容 | 旧・下請代金支払遅延等防止法 | 現・取適法（2026-01-01施行） |
|---|---|---|
| 定義（適用範囲） | 2条 | 2条（従業員数基準が追加） |
| 支払期日（受領日から60日以内） | 2条の2 | **3条** |
| 書面の交付・明示義務 | 3条 | **4条** |
| 禁止行為 | 4条 | **5条**（協議に応じない一方的な代金決定が追加） |
| 遅延利息 | 4条の2 | **6条** |
| 書類の作成・保存 | 5条 | **7条** |

## 2. 日本法令索引 — 改正沿革・制定経緯

<https://hourei.ndl.go.jp/#/>

国立国会図書館。e-Govが「今どうなっているか」を答えるのに対し、こちらは「いつ・どの改正で・どう変わったか」を答える。WebFetch で参照する。

使う場面:

- 契約書が古い法令名・旧条文番号を引用している場合、それが現在どの条文に対応するかを追う
- 「この規制はいつからか」を確認する（契約締結時点の法令を問題にするとき）
- 改正法の公布日・施行日、附則の経過措置を確認する
- 廃止された法令や、名称変更前の法令を探す

e-Gov法令APIにも改正履歴を返す `law_revisions/{law_id}` エンドポイントがあるので、単純な改正履歴ならこちらの方が速い:

```bash
curl -s "https://laws.e-gov.go.jp/api/2/law_revisions/331AC0000000120" | head -c 2000
```

## 3. 厚労省 労働契約ポータル — 労働法の行政解釈と裁判例

<https://roukeiseminar.mhlw.go.jp/rules.html>

**雇用契約・労働条件通知書をレビューするときは必ず当たる。** 労基法・労働契約法の条文だけでは、「更新の期待が認められるか」「この不利益変更は合理的か」「この解雇は有効か」といった判断ができない。このサイトは行政の解釈と裁判例の相場をまとめている。

| ページ | 内容 | 使う場面 |
|---|---|---|
| <https://roukeiseminar.mhlw.go.jp/contract.html> | 労働契約の締結 | 明示事項、労働条件の設定 |
| <https://roukeiseminar.mhlw.go.jp/alteration.html> | 労働条件の変更 | 包括的変更権条項、就業規則の不利益変更 |
| <https://roukeiseminar.mhlw.go.jp/expiration.html> | 労働契約の終了 | 解雇条項、雇止め、退職の申出期限 |
| <https://roukeiseminar.mhlw.go.jp/indefinite.html> | 無期転換ルール | 更新上限条項、通算5年、申込権の放棄 |
| <https://roukeiseminar.mhlw.go.jp/rules-case.html> | こんなときは？ | 個別ケースの当てはめ |
| <https://roukeiseminar.mhlw.go.jp/law.html> | 裁判事例集 | 類似事案の結論を探す |

WebFetch で読み込む際は、「この条項に関連する行政解釈と裁判例の傾向」を prompt に書いて必要部分だけ取ること。

## 4. 調査の型

1. **条項を読んで、当たるべき法令の見当をつける**（`checkpoints-common.md` と類型ファイルに主要な法令名と条番号が書いてある）
2. **条文を取得する** — `python3 scripts/egov.py article <法令> <条>`
3. **条文に当てはめる** — 強行規定か任意規定かを見る。強行規定に反する条項は無効なので「契約書にこう書いてあっても効力はない」と書ける。任意規定なら「契約で上書きされているので、この内容で拘束される」と書く
4. **解釈が分かれる論点なら、行政解釈・裁判例を探す** — 労働法なら労働契約ポータル、沿革が問題なら日本法令索引、それ以外は所管官庁（公正取引委員会、経済産業省、国土交通省、個人情報保護委員会）のガイドラインを WebSearch / WebFetch で探す
5. **取得できなかったら、そう書く** — 「条文未確認」と明記し、確認すべき法令名と条番号だけを示す。うろ覚えの条文番号を添えるくらいなら、書かない方がよい

## 5. 強行規定・任意規定の区別

この区別を外すと指摘の結論が逆になるので、必ず意識する。

**強行規定（契約で変更できない）の代表例**

- 労働基準法の労働条件に関する規定（労基法13条により、下回る部分は無効となり法定基準に置換）
- 借地借家法30条・37条が列挙する借主保護規定
- 取適法・フリーランス法の禁止行為（**合意があっても違反は違反**）
- 利息制限法の上限金利
- 消費者契約法8条〜10条（相手が消費者の場合）
- 民法465条の2（個人根保証の極度額。定めがなければ保証契約自体が無効）

**任意規定（契約で上書きできる）の代表例**

- 民法の契約各則の多く（危険負担、契約不適合責任の期間、解除の要件、報酬の支払時期など）
- 商法526条（買主の検査・通知義務）

任意規定を上書きしている条項を見つけたら、「民法の原則ではAだが、本契約はBに変更している。その結果こうなる」という形で書くと、依頼者に効果が伝わる。
